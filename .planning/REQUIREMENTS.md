## v2.0.0 Milestone — Architectural Cleanup & Breaking Fixes

**Rationale.** Every item below requires a breaking change or is structural work that would be invalidated by the planned `ARCH-01..05` decomposition. Bundling them into a single v2.0.0 release means downstream consumers absorb one migration, not many.

**Scope expanded (2026-04-20 lean refactor):** Items originally slated for v1.0.2 have been moved here because v2's architectural refactor will rewrite the files/surfaces they touch — building them in v1.0.2 would be wasted work.

**Release target:** v2.0.0
**Migration guide:** required
**Branch:** `master` (v2 development continues here; v1.0.2 lives on its own `v1.0.2` branch)

---

### Architecture (Structural — Core of v2.0.0)

These items share the same extracted interfaces and should ship together.

- **ARCH-01**: Extract `QueryTranslator<T>` core — `SCondition` → adapter query builder, shared across TypeORM, Drizzle, MikroORM. Eliminates three-way code drift; future bug fixes (like v1.0.2's QUALITY-02/03) would land once, not per-adapter
- **ARCH-02**: Extract `JoinResolver` from `packages/typeorm/src/typeorm-crud.service.ts:560-598` — isolates join strategy so split-query support (PERF-01) becomes a pluggable strategy instead of a rewrite
- **ARCH-03**: Extract `InputSanitizer` with strict column-allowlist strategy (**absorbs the former SEC-01**) — shared across all three adapters; replaces the three duplicated regex denylists with one allowlist driven by `entityColumnsHash`
- [x] **ARCH-04** (COMPLETE 2026-04-22, Phase 5): Slim `packages/typeorm/src/typeorm-crud.service.ts` to orchestration only — shipped at **249 lines** (from 472-line Phase 5 baseline; 1023-line original Phase 3 start). Delegates to ARCH-01/02/03 extractions. Reviewer approved. See `.planning/phases/05-arch-04-slim-typeormcrudservice/05-07-SUMMARY.md`.
- **ARCH-05**: Align `packages/drizzle/src/drizzle-crud.service.ts` and `packages/mikro-orm/src/mikro-orm-crud.service.ts` to the same orchestration pattern — one mental model across all adapters, which also eliminates duplicated behavior drift

### Adapters

- **ADAPTER-01**: Prisma adapter at parity with TypeORM/Drizzle/MikroORM — substantially cheaper to add once ARCH-01..05 land (new adapter implements the shared interfaces rather than duplicating 1000 lines)

### Security

- **SEC-02**: `@CrudAuth` persist runtime key validation at `packages/request/src/request-query.parser.ts:147-148` — breaking because it throws on previously-silent typos
- **SEC-03**: Wrap partial-update handlers (`updateOne`, `replaceOne`, `deleteOne`) in scoped transactions across all 3 adapters. Discovered by Phase 1 `P1-T6` audit (2026-04-20) — current read-modify-write pattern has a race window under concurrent requests to the same entity (lost-update scenario). LOC cost is small but structural implications (consumer `@Override()` extensions, transaction nesting / deadlock potential) make this a v2 item. Naturally lands alongside `ARCH-04` where the service is decomposed into read/merge/write steps anyway. Full analysis in `.planning/phases/01-correctness-ci-green/audit-notes.md`

### Types (Public Signatures — Breaking)

- **TYPES-01**: Drizzle `protected db: any` → typed constructor signature — breaking for consumer subclasses
- **TYPES-02**: `any` reduction on **public** MikroORM method signatures — breaking for subclasses that rely on `any` permissiveness
- **TYPES-05**: Stop importing `@nestjs/swagger/dist/types/swagger-enum.type` internal type (`packages/core/src/interfaces/params-options.interface.ts:1`) — may require typing shift visible to consumers
- ~~**TYPES-06**~~: ~~Remove `skipLibCheck: true` from `packages/drizzle/tsconfig.json:3`~~ — **PERMANENTLY DEFERRED** (2026-04-21 research finding). drizzle-orm v0.45.1 has 50+ internal type declaration errors unrelated to `@nestjs-crud/drizzle` source (missing `gel` module, `getSQL` absent from `SQLWrapper` implementors, SingleStore incomplete). Removing `skipLibCheck` would expose these to consumers and block their builds. Mitigation: bump `peerDependencies` min to `>=0.40.0` and document the known limitation. Re-evaluate when drizzle-orm ships clean declarations.

### Types (Internal — Subsumed by ARCH)

Moved from v1.0.2; these files get rewritten by ARCH-01 / ARCH-05, so the `any`-reduction happens as a side effect of structural refactor.

- **TYPES-03**: Reduce `any` count in `packages/core/src/crud/reflection.helper.ts` — subsumed by ARCH-01 (`QueryTranslator` extraction rewrites this file)
- **TYPES-04**: Reduce `any` count in `packages/mikro-orm/src/mikro-orm-crud.service.ts` — subsumed by ARCH-05 (MikroORM adapter aligned to orchestration pattern)

### Observability

### Build / Engines

- **BUILD-01**: Declare `engines.node` across all 6 `package.json` files (Node 22.x inferred from `@types/node`) — borderline-breaking to add post-hoc; safer in v2 alongside the other breaking items
- **BUILD-01 (peerDependencies audit)**: Fix under-declared peer deps across the adapter packages:
  - `packages/typeorm/package.json` — **no `peerDependencies` key exists**. Add `typeorm: "^0.3.0"`, `@nestjs/typeorm: "^10.0.0"` (or current compatible), `@nestjs-crud/core: "^2.0.0"`, `@nestjs/common: "^10.0.0"`.
  - `packages/drizzle/package.json` — has `drizzle-orm: ">=0.36.0"` but missing `@nestjs-crud/core: "^2.0.0"` and `@nestjs/common: "^10.0.0"`.
  - `packages/mikro-orm/package.json` — has the MikroORM peers + `@nestjs-crud/core: "^1.0.0"`; bump core peer to `^2.0.0` for v2 ship (also touched by DEPS-01).
  - `packages/core/package.json` — has `class-transformer` + `class-validator`; add `@nestjs/common: "^10.0.0"` (currently implicit via NestJS import chain; consumers get no install warning if missing).
  - Consumer impact: `npm install @nestjs-crud/typeorm` currently gives ZERO peer warning when TypeORM is absent or pinned to v0.2 — silent runtime failures. Fixing this is packaging hygiene + a usability win.

### Dependencies

- **DEPS-01**: Bump MikroORM to v7 across the stack. Breaking peer change for consumers on v6.
  - Root `package.json` devDeps: `@mikro-orm/core` and `@mikro-orm/sqlite` already at `^7.0.11`. `@mikro-orm/knex` still `^6.6.13` — bump to v7.
  - `packages/mikro-orm/package.json` peerDependencies: `@mikro-orm/core`/`@mikro-orm/knex` currently `>=6.0.0` — bump to `>=7.0.0`.
  - Must land **early in v2** (ideally Phase 3) so ARCH-01 `QueryTranslator<Q, W>` type params and TYPES-02 public-signature tightening target v7's `FilterQuery<T>`, `RequiredEntityData<T>`, `EntityMetadata<T>` shapes — not v6.
  - Migration guide: v6→v7 consumer impact (API changes in MikroORM itself, not just our adapter).

### Performance

### Why bundle rather than split into v1.1, v1.2, v2

Consumer migration cost is dominated by *count of breaking releases*, not *size per release*. Shipping one well-documented v2.0.0 with a migration guide is easier for downstream users to plan for than 3–4 staggered breaking minors.
